## Public API

### Exports (from `index.ts`)

1. **`createHonoHandler(options: HonoHandlerOptions): (c: HonoContext) => Promise<Response>`**
   - Factory function that creates a Hono-compatible handler
   - Takes `{ facade: HttpFacade }` as options
   - Returns async handler function

2. **`module: ModuleMeta<HonoHttpAdapterModuleOptions>`**
   - Kernel module metadata
   - Name: `@comity/http-hono`
   - Version: `1.0.0`
   - Dependencies: `@comity/primitives`, `@comity/kernel`, `@comity/http`

3. **Types**
   - `HonoHandlerOptions` - Options for `createHonoHandler`
   - `HonoHttpAdapterModuleOptions` - Options for kernel module

## Implementation Details

### Context Mapping (`adapter/context.ts`)

**Function**: `createHttpContextFromHono(c: HonoContext, eventBus?: EventBus): HttpContext`

Maps Hono Context to HttpContext:
- ✅ Generates unique request ID via `crypto.randomUUID()`
- ✅ Extracts HTTP method, URL, headers (lowercased)
- ✅ Parses query parameters (supports multiple values)
- ✅ Extracts path parameters from Hono
- ✅ Creates mutable state via `createHttpState()`
- ✅ Provides abort signal from `c.req.raw.signal`
- ✅ Stores raw request body in `rawBody`
- ✅ Implements `setResponse()` with guard against double-setting

### Response Mapping (`adapter/response.ts`)

**Function**: `mapHttpResultToResponse(result: HttpResult): Response`

Maps HttpResult to Web Standard Response:

**Success case** (`ok: true`):
- ✅ Extracts `status`, `headers`, `body` from `result.response`
- ✅ Handles different body types:
  - `string` → text/plain
  - `Uint8Array` / `ArrayBuffer` → application/octet-stream
  - `ReadableStream` → streaming response
  - `object` → JSON serialization with application/json
- ✅ Auto-sets Content-Type if not present
- ✅ Returns Web Standard Response

**Error case** (`ok: false`):
- ✅ Uses `error.status` for HTTP status code
- ✅ Serializes error as JSON with `code`, `message`, `details`
- ✅ Sets Content-Type to application/json
- ✅ Does NOT leak sensitive error data (no `cause`)

### Handler (`adapter/hono-handler.ts`)

**Function**: `createHonoHandler(options: HonoHandlerOptions): (c: HonoContext) => Promise<Response>`

Request flow:
1. Creates `HttpContext` from Hono context
2. Calls `facade.handle(ctx)` 
3. Maps `HttpResult` to `Response`
4. Catches any unhandled exceptions → returns HTTP 500

Error handling:
- ✅ Try-catch around `facade.handle`
- ✅ Returns 500 with generic error on exception
- ✅ Error code: `http:internal`
- ✅ No sensitive data leaked

### Module (`module.ts`)

**Export**: `module: ModuleMeta<HonoHttpAdapterModuleOptions>`

- Name: `@comity/http-hono`
- Version: `1.0.0`
- Dependencies: `@comity/primitives`, `@comity/kernel`, `@comity/http`
- Setup function: Returns success with no-op (reserved for future use)
- Does NOT register services by default
- Works independently of kernel

## Architecture Compliance

### ✅ Pure Adapter
- No business logic
- Only performs type conversions
- Stateless operations
- No global state

### ✅ Minimal API
- Only 3 exports: `createHonoHandler`, `module`, types
- No helpers or utilities
- No re-exports of internals
- Clean separation of concerns

### ✅ Error Handling
- Unhandled exceptions → HTTP 500
- Error results → mapped via `error.status`
- No custom error logic
- No sensitive data leaks

### ✅ HTTP Context
- Request: immutable snapshot
- State: mutable, per-request
- Signal: from Hono request
- setResponse: guards against double-setting

### ✅ Events
- No new events defined
- Ready for kernel event bus integration (optional)
- No sensitive data in events

### ✅ Kernel Integration
- Optional module export
- Works without kernel
- No forced service registration
- Clean separation
